1. Window Functions

Window Function adalah fitur terkuat di SQL modern yang memungkinkan perhitungan di sekelompok baris tanpa melakukan grouping. Berbeda dengan aggregate function yang menggabungkan baris menjadi satu, window function mempertahankan setiap baris individual dan menambahkan nilai perhitungan di setiap baris.

Ini adalah fitur yang paling sering digunakan dalam analisis data, reporting, dan kasus ranking.

Fungsi window yang umum: ROW_NUMBER(), RANK(), DENSE_RANK(), LAG(), LEAD(), SUM() OVER(), AVG() OVER()

📝 Contoh:

SELECT 
  nama_produk,
  kategori,
  penjualan,
  RANK() OVER (PARTITION BY kategori ORDER BY penjualan DESC) AS ranking
FROM products;

✅ Contoh ranking penjualan per kategori

SELECT 
  tanggal,
  total,
  LAG(total, 1) OVER (ORDER BY tanggal) AS total_bulan_sebelumnya,
  ROUND(((total - LAG(total, 1) OVER (ORDER BY tanggal)) / LAG(total, 1) OVER (ORDER BY tanggal)) * 100, 2) AS persentase_pertumbuhan
FROM penjualan_bulanan;

✅ Contoh perbandingan dengan bulan sebelumnya

2. Common Table Expression (CTE)

CTE adalah cara menulis subquery yang dapat dibaca dan dapat direferensikan beberapa kali dalam query utama. CTE membuat query kompleks menjadi modular, mudah dibaca, dan dapat di recursive.

Keunggulan CTE:

  • ✅ Bisa dijalankan secara recursive
  • ✅ Lebih mudah dibaca daripada nested subquery
  • ✅ Dapat direferensikan berkali-kali
  • ✅ Cocok untuk query hierarchical dan tree structure

📝 Contoh:

WITH penjualan_per_kota AS (
  SELECT kota, SUM(total) AS total_penjualan
  FROM orders
  GROUP BY kota
)
SELECT * FROM penjualan_per_kota 
WHERE total_penjualan > 10000000
ORDER BY total_penjualan DESC;

✅ CTE dasar untuk query bersih

WITH RECURSIVE kategori_hirarki AS (
  SELECT id, nama, parent_id, 0 AS level
  FROM categories WHERE parent_id IS NULL
  
  UNION ALL
  
  SELECT c.id, c.nama, c.parent_id, kh.level + 1
  FROM categories c
  INNER JOIN kategori_hirarki kh ON c.parent_id = kh.id
)
SELECT * FROM kategori_hirarki;

✅ Recursive CTE untuk struktur hirarki

3. Index & Query Optimization

Index adalah struktur data yang mempercepat pencarian data di tabel, seperti index di buku. Tanpa index, database akan melakukan FULL TABLE SCAN yang sangat lambat ketika data sudah jutaan baris.

Jenis Index:

  • ✅ Primary Key Index
  • ✅ Secondary Index
  • ✅ Composite Index
  • ✅ Unique Index
  • ✅ Full Text Index

Aturan penting index:

  • Index mempercepat SELECT, tapi memperlambat INSERT/UPDATE/DELETE
  • Jangan over index
  • Gunakan index di kolom yang sering dipakai di WHERE, JOIN, ORDER BY

📝 Contoh:

-- Index biasa
CREATE INDEX idx_orders_user_id ON orders(user_id);

-- Composite Index
CREATE INDEX idx_orders_status_created ON orders(status, created_at);

-- Analisa query dengan EXPLAIN
EXPLAIN ANALYZE 
SELECT * FROM orders WHERE user_id = 123 AND status = 'selesai';

✅ Membuat index dan analisa query

4. Database Transaction

Transaction adalah sekelompok operasi SQL yang dianggap sebagai satu kesatuan kerja. Semua operasi di dalam transaction harus berhasil semua, jika ada satu yang gagal maka semua dibatalkan (rollback).

Properti ACID:

  • Atomicity: Semua atau tidak sama sekali
  • Consistency: Data selalu konsisten
  • Isolation: Transaction tidak saling mengganggu
  • Durability: Data yang sudah di commit permanen

📝 Contoh:

START TRANSACTION;

UPDATE rekening SET saldo = saldo - 500000 WHERE id = 1;
UPDATE rekening SET saldo = saldo + 500000 WHERE id = 2;

-- Cek jika semua benar
SELECT saldo FROM rekening WHERE id IN (1,2);

-- Jika semua ok
COMMIT;

-- Jika ada kesalahan
-- ROLLBACK;

✅ Transaction transfer uang

5. Stored Procedure & Trigger

Stored Procedure adalah kode SQL yang disimpan di database dan dapat dipanggil berulang kali. Trigger adalah prosedur yang otomatis berjalan ketika terjadi event tertentu (INSERT/UPDATE/DELETE) di tabel.

Keduanya digunakan untuk mengeksekusi logika bisnis secara langsung di level database.

📝 Contoh:

CREATE PROCEDURE BuatOrder(
  IN p_user_id INT,
  IN p_total INT,
  OUT p_order_id INT
)
BEGIN
  INSERT INTO orders (user_id, total, status) VALUES (p_user_id, p_total, 'pending');
  SET p_order_id = LAST_INSERT_ID();
  
  INSERT INTO log_aktivitas (aksi, keterangan) VALUES ('ORDER_BARU', CONCAT('Order dibuat id: ', p_order_id));
END;

✅ Stored Procedure untuk membuat order

CREATE TRIGGER after_order_insert
AFTER INSERT ON order_items
FOR EACH ROW
BEGIN
  UPDATE products SET stok = stok - NEW.kuantitas WHERE id = NEW.produk_id;
END;

✅ Trigger update stok otomatis

6. View & Materialized View

View adalah query yang disimpan sebagai tabel virtual, tidak menyimpan data fisik hanya menyimpan query. Materialized View menyimpan hasil query secara fisik dan di refresh secara periodik, sangat cocok untuk reporting.

View digunakan untuk:

  • ✅ Menyederhanakan query kompleks
  • ✅ Security (menyembunyikan kolom sensitif)
  • ✅ Abstraksi lapisan data

📝 Contoh:

CREATE VIEW vw_laporan_penjualan AS
SELECT 
  DATE(o.created_at) AS tanggal,
  u.nama AS nama_user,
  o.no_order,
  o.total,
  o.status
FROM orders o
JOIN users u ON o.user_id = u.id
WHERE o.status = 'selesai';

-- Gunakan view seperti tabel biasa
SELECT * FROM vw_laporan_penjualan WHERE tanggal >= '2026-01-01';

✅ Membuat View laporan penjualan
