Pengertian Dockerfile dan Contoh Pembuatan

Module ini menjelaskan secara mendalam apa itu Dockerfile, sintaks dasar, best practice, dan contoh pembuatan Dockerfile untuk berbagai jenis aplikasi. Setelah mempelajari module ini kamu akan bisa membuat Dockerfile sendiri untuk aplikasi kamu.

🎯 Learning Objectives

  • ✅ Memahami apa itu Dockerfile dan fungsinya
  • ✅ Menghafal dan memahami instruksi Dockerfile yang paling sering digunakan
  • ✅ Bisa membuat Dockerfile untuk Node.js, Python, dan aplikasi web
  • ✅ Memahami konsep Layer dan Cache di Docker
  • ✅ Menerapkan best practice untuk membuat image yang kecil dan aman
  • ✅ Menggunakan Multi Stage Build
  • ✅ Memahami perbedaan CMD vs ENTRYPOINT

1. Apa Itu Dockerfile?

Dockerfile adalah file teks biasa yang berisi daftar instruksi yang akan dijalankan secara berurutan oleh Docker untuk membangun sebuah image.

Dockerfile memungkinkan kamu:

  • ✅ Mendefinisikan environment aplikasi secara kode
  • ✅ Membuat image secara otomatis dan berulang
  • ✅ Membagikan cara build image ke seluruh tim
  • ✅ Mendokumentasikan langkah-langkah build aplikasi

📝 Contoh:

# Ini adalah contoh Dockerfile paling sederhana
FROM alpine:3.18

RUN apk add --no-cache nginx

CMD ["nginx", "-g", "daemon off;"]

2. Instruksi Dasar Dockerfile

Instruksi yang paling sering digunakan di Dockerfile:

Instruksi Fungsi
FROM Menentukan base image yang akan digunakan
RUN Menjalankan perintah di dalam build stage
COPY Menyalin file dari host ke dalam image
WORKDIR Menentukan direktori kerja untuk instruksi selanjutnya
ENV Mengatur environment variable
EXPOSE Mendokumentasikan port yang akan digunakan
CMD Perintah default ketika container berjalan
ENTRYPOINT Perintah yang akan selalu dijalankan

3. Urutan Eksekusi dan Layer

Setiap baris instruksi di Dockerfile akan membuat sebuah layer baru di image. Docker akan menyimpan cache setiap layer, jadi jika kamu mengubah baris di tengah Dockerfile, hanya layer setelahnya yang akan di build ulang.

✅ Untuk memaksimalkan cache:

  • Letakkan instruksi yang jarang berubah DIATAS
  • Letakkan instruksi yang sering berubah DIBAWAH
  • Gabungkan beberapa RUN menjadi satu baris untuk mengurangi jumlah layer

4. Contoh Dockerfile Node.js

📝 Contoh:

# Gunakan base image official Node.js
FROM node:20-alpine

# Set working directory
WORKDIR /app

# Copy file package.json terlebih dahulu untuk cache
COPY package*.json ./

# Install dependensi
RUN npm ci --only=production

# Copy kode aplikasi
COPY . .

# Expose port
EXPOSE 3000

# User non root untuk keamanan
USER node

# Perintah menjalankan aplikasi
CMD ["node", "server.js"]

5. Contoh Dockerfile Python

📝 Contoh:

FROM python:3.11-slim

WORKDIR /app

ENV PYTHONDONTWRITEBYTECODE 1
ENV PYTHONUNBUFFERED 1

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 8000

CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]

6. Multi Stage Build

Multi Stage Build memungkinkan kamu menggunakan banyak stage di dalam satu Dockerfile. Kamu bisa menggunakan stage untuk build aplikasi dan hanya menyalin hasil akhir ke image final.

📝 Contoh:

# 🔨 STAGE 1: Build aplikasi
FROM node:20-alpine AS builder

WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# 🚀 STAGE 2: Production Image
FROM node:20-alpine

WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production

# Salin hanya hasil build dari stage builder
COPY --from=builder /app/dist ./dist

EXPOSE 3000
CMD ["node", "dist/server.js"]

7. CMD vs ENTRYPOINT

Ini adalah salah satu konsep yang paling sering disalahpahami:

CMD

Perintah default yang bisa diganti dengan mudah ketika menjalankan container

ENTRYPOINT

Perintah yang akan selalu dijalankan, tidak bisa diganti kecuali dengan --entrypoint

8. Best Practice Dockerfile

  • ✅ Gunakan base image yang sekecil mungkin (alpine > slim > full)
  • ✅ Jalankan aplikasi dengan user non-root
  • ✅ Gunakan .dockerignore untuk mengecualikan file yang tidak perlu
  • ✅ Satu container satu proses
  • ✅ Jangan menyimpan data di dalam container
  • ✅ Gunakan Multi Stage Build
  • ✅ Minimalkan jumlah layer
  • ✅ Jangan gunakan latest tag

9. Perintah Build Image

📝 Contoh:

# Build image dengan nama dan tag
docker build -t nama-aplikasi:v1.0 .

# Build tanpa menggunakan cache
docker build --no-cache -t nama-aplikasi:v1.0 .

# Build dengan target stage tertentu
docker build --target builder -t nama-aplikasi:dev .
