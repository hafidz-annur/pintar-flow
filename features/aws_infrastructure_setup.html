Setup AWS Infrastructure (VPC, EC2, ALB, WAF)

Module ini akan mengajarkan kamu step by step bagaimana membangun arsitektur infrastructure di AWS Cloud yang production ready. Kamu akan mempelajari dan mempraktekkan langsung pembuatan VPC, EC2 Instance, Application Load Balancer, dan Web Application Firewall dengan konfigurasi best practice.

1. Pengenalan AWS VPC (Virtual Private Cloud)

VPC adalah jaringan virtual pribadi yang kamu buat di lingkungan AWS. VPC merupakan dasar dari seluruh infrastructure AWS kamu, semua resource AWS seperti EC2, RDS, ALB harus berada di dalam sebuah VPC.

Dengan VPC kamu memiliki kontrol penuh terhadap:

  • Rentang IP Address yang kamu gunakan (CIDR Block)
  • Pembagian Subnet
  • Routing table
  • Network Access Control List
  • Security Group

Setiap VPC terisolasi secara default dari jaringan lain dan dari internet.

📝 Contoh:

VPC CIDR: 10.0.0.0/16 (Total 65536 IP Address)

Dibagi menjadi:
✅ Public Subnet 1A: 10.0.1.0/24
✅ Public Subnet 1B: 10.0.2.0/24
✅ Private Subnet 1A: 10.0.10.0/24
✅ Private Subnet 1B: 10.0.11.0/24

2. Membuat VPC & Komponen Jaringan

Langkah pertama membangun infrastructure adalah membuat VPC dan komponen pendukungnya:

  1. Internet Gateway (IGW): Gateway yang menghubungkan VPC kamu dengan internet public
  2. Route Table: Menentukan kemana traffic jaringan akan diarahkan
  3. Subnet: Pembagian jaringan VPC menjadi bagian lebih kecil
  4. NAT Gateway: Memungkinkan resource di Private Subnet mengakses internet tapi tidak bisa diakses dari internet
  5. Security Group: Firewall level instance yang mengontrol inbound dan outbound traffic

💡 Best Practice:

Selalu buat Subnet di minimal 2 Availability Zone untuk High Availability.

📝 Contoh:

Langkah-langkah pembuatan VPC di AWS Console:
1. Buka VPC Dashboard → Your VPCs → Create VPC
2. Nama VPC: production-vpc
3. IPv4 CIDR: 10.0.0.0/16
4. Buat Internet Gateway dan attach ke VPC
5. Buat 2 Public Subnet di AZ a dan b
6. Buat 2 Private Subnet di AZ a dan b
7. Buat Route Table untuk Public Subnet dengan default route ke IGW
8. Buat NAT Gateway di Public Subnet
9. Buat Route Table untuk Private Subnet dengan default route ke NAT Gateway

3. Launch EC2 Instance

EC2 adalah virtual server di AWS yang menjadi tempat kamu menjalankan aplikasi. EC2 berada di dalam Subnet dan memiliki Security Group sebagai firewall.

Ketika membuat EC2 kamu harus menentukan:

  • Amazon Machine Image (AMI): Sistem Operasi yang akan digunakan
  • Instance Type: Spesifikasi CPU dan Memory
  • Key Pair: SSH key untuk mengakses server
  • VPC & Subnet: Tempat EC2 akan ditempatkan
  • Security Group: Aturan firewall
  • Storage: Ukuran dan tipe EBS Volume

⚠️ Penting:

Jangan pernah menempatkan aplikasi backend di Public Subnet, selalu gunakan Private Subnet.

📝 Contoh:

# Konfigurasi EC2 Web Server:
✅ AMI: Amazon Linux 2
✅ Instance Type: t2.micro
✅ Subnet: Private Subnet
✅ Key Pair: aws-production
✅ Security Group:
  Inbound:
    - HTTP 80 dari ALB Security Group
    - SSH 22 dari IP kantor saja
✅ User Data:
#!/bin/bash
yum update -y
yum install -y httpd
systemctl start httpd
systemctl enable httpd
echo "
Hello dari EC2 Instance $(hostname -f)
" > /var/www/html/index.html

4. Setup Application Load Balancer (ALB)

Application Load Balancer adalah Layer 7 Load Balancer yang berfungsi mendistribusikan traffic HTTP/HTTPS secara merata ke beberapa EC2 Instance dibelakangnya.

ALB berjalan di Public Subnet dan menjadi satu-satunya entry point yang terbuka ke internet. Semua user akan mengakses aplikasi melalui ALB, tidak langsung ke EC2.

Keuntungan menggunakan ALB:

  • High Availability
  • SSL Termination
  • Health Check
  • Path based routing
  • Automatic scaling

📝 Contoh:

Langkah pembuatan ALB:
1. Buka EC2 Dashboard → Load Balancers → Create Load Balancer
2. Pilih Application Load Balancer
3. Skema: Internet-facing
4. Pilih VPC dan semua Public Subnet
5. Buat Security Group ALB:
   Inbound: HTTP 80, HTTPS 443 dari 0.0.0.0/0
6. Buat Target Group dan register EC2 Instance yang sudah dibuat
7. Konfigurasi Health Check di path /health
8. Pastikan Health Status menjadi Healthy

5. Konfigurasi AWS WAF (Web Application Firewall)

AWS WAF adalah Web Application Firewall yang melindungi aplikasi kamu dari serangan web umum seperti SQL Injection, Cross Site Scripting (XSS), DDoS, dan exploit umum lainnya.

WAF bekerja di depan Application Load Balancer dan memeriksa setiap request sebelum sampai ke aplikasi kamu. Kamu bisa membuat aturan kustom atau menggunakan managed rules yang sudah disediakan AWS.

Managed Rules AWS yang wajib diaktifkan:

  • AWSManagedRulesCommonRuleSet
  • AWSManagedRulesSQLiRuleSet
  • AWSManagedRulesKnownBadInputsRuleSet
  • AWSManagedRulesAmazonIpReputationList

📝 Contoh:

Langkah implementasi WAF:
1. Buka WAF & Shield Dashboard
2. Buat Web ACL baru
3. Resource Type: Application Load Balancer
4. Pilih Region dan ALB yang sudah dibuat
5. Tambahkan AWS Managed Rules yang diperlukan
6. Set Default Action: Allow
7. Aktifkan CloudWatch Metrics dan logging
8. Deploy Web ACL ke ALB
9. Test dengan mengirim request berbahaya untuk memastikan WAF bekerja

6. Arsitektur Akhir & Best Practice

Setelah semua komponen selesai dibuat, kamu akan memiliki arsitektur 3 Tier standar yang merupakan best practice industri:

  1. Edge Tier: AWS WAF
  2. Load Balancer Tier: Application Load Balancer di Public Subnet
  3. Web Tier: EC2 Instance di Private Subnet
  4. Database Tier: RDS di Private Subnet (terpisah)

Semua traffic dari internet hanya bisa sampai ke ALB, tidak ada resource lain yang terekspos langsung ke internet.

Checklist Keamanan Wajib:

  • ✅ Semua EC2 di Private Subnet
  • ✅ Security Group menggunakan prinsip least privilege
  • ✅ SSH hanya diizinkan dari IP terpercaya
  • ✅ Semua password dan key dirotasi secara rutin
  • ✅ CloudTrail diaktifkan untuk audit semua aktivitas

📝 Contoh:

🔒 Alur Traffic Production:

User → Internet → AWS WAF → Application Load Balancer → EC2 Instance Private Subnet → RDS Database Private Subnet

✅ Tidak ada resource lain yang memiliki Public IP
✅ Semua komunikasi internal menggunakan private IP
✅ Semua access terkontrol dengan Security Group
✅ Semua aktivitas terlog di CloudWatch
